# B1-1 동료평가 대비 가이드

## 1. 이 과제가 뭔가요?
Linux 서버에 보안을 설정하고 모니터링을 자동화하는 과제.

## 2. 평가 예상 질문

### 학습 목표 #1: SSH 보안 설정이 기본 보안인 이유

Q1. SSH 포트 변경이 왜 보안인가?
A. 기본 포트 22는 전 세계 자동 스캔 도구의 기본 타겟입니다. 포트를 20022로 변경하면 대부분의 자동 스캔을 회피할 수 있습니다. 완벽한 방어는 아니지만(포트 스캔하면 찾을 수 있음), 무차별 대입 공격의 대부분을 줄일 수 있습니다. 추가로 `PasswordAuthentication no`를 설정하여 비밀번호 로그인을 막고 키 기반 인증만 허용했습니다.

### 학습 목표 #2: UFW 방화벽 최소 권한 정책

Q2. UFW 방화벽 정책을 어떻게 구성했나요?
A. 기본 정책은 "들어오는 것은 전부 차단(deny incoming), 나가는 것은 전부 허용(allow outgoing)"으로 설정했습니다. 그 다음 필요한 포트만 선택적으로 열었습니다: SSH용 20022/tcp, 에이전트 앱용 15034/tcp. 이것이 "최소 권한" 원칙입니다 — 필요한 것만 열고 나머지는 전부 닫습니다. 모든 포트를 열어두면 공격 면적이 커지고, 전부 닫으면 서비스가 안 됩니다. 중간에 "필요한 것만"이 정답입니다.

### 학습 목표 #3: 역할 기반 계정/그룹 권한 분리

Q3. 역할 기반 권한 분리 이유?
A. 최소 권한 원칙. agent-admin(운영자), agent-dev(개발자) 등 역할별로 계정을 나누고, 각 역할이 필요한 리소스만 접근하도록 그룹과 권한을 설정했습니다. 한 계정이 모든 것을 할 수 있으면 실수나 악의적 행동 시 전체 시스템이 위험해집니다.

### 학습 목표 #4: 환경 변수로 실행 환경 고정

Q4. 환경변수로 실행 환경을 고정하는 이유?
A. 배포 일관성. AGENT_HOME, AGENT_PORT, AGENT_LOG_DIR 등을 환경변수로 설정하면, 어디서 실행하든 같은 경로/포트/설정을 사용합니다. 코드에 경로를 하드코딩하면 환경이 바뀔 때마다 코드를 수정해야 하지만, 환경변수는 코드 수정 없이 설정만 바꾸면 됩니다.

### 학습 목표 #5: 모니터링 데이터 수집 및 분석 흐름

Q5. 모니터링 데이터 수집부터 분석까지의 흐름을 설명해주세요.
A. 세 단계로 동작합니다:
1. **수집**: `monitor.sh`가 cron으로 매분 실행되어 프로세스 상태, 포트, CPU, 메모리, 디스크 사용량을 수집합니다.
2. **저장**: 수집한 데이터를 타임스탬프와 함께 `/var/log/agent-app/monitor.log`에 한 줄씩 기록합니다. 로그가 10MB를 넘으면 자동으로 rotate + gzip 압축합니다.
3. **분석**: `report.sh`가 로그 파일을 읽어 지정된 시간 구간의 평균/최대 CPU, 메모리, 디스크 사용량을 awk로 계산해서 요약 보고서를 출력합니다.

### 학습 목표 #6: 로그 보존 정책

Q6. 로그 보존 정책이 왜 필요한가?
A. 장애 발생 시 원인 추적의 유일한 단서. 로그 없으면 원인 추론이 불가능합니다. 하지만 로그를 무한정 쌓으면 디스크가 가득 차서 시스템이 멈춥니다. 그래서 보존 정책이 필요합니다 — 이 프로젝트에서는 로그 파일이 10MB를 넘으면 rotate + gzip 압축하고, 최대 10개 파일까지만 보관합니다.
